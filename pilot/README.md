# Nimbus Travel 多城市评价测试版

导游手填官方团号、城市、姓名，生成本站游客二维码。游客可选择中文、英语、俄语或西班牙语，打开即显示本站资料。运营按团号查询各站评价。本目录中的测试版使用独立的数据表。

## 直接体验

用 Chrome 或 Edge 打开生成的 `Nimbus-Feedback-Pilot.html`。生成三个相同团号、不同城市的二维码，用「打开游客表单」在同一浏览器提交，再点「运营后台」查询。此模式使用浏览器本地数据。

## 电脑与局域网联调

需要 Node.js 20 或更新版本。解压源码后，从 `source/` 目录启动。直接使用 GitHub 仓库时，从仓库根目录启动。

```sh
PILOT_OPS_PIN='替换为至少12字符的测试访问码' node pilot/serve.mjs
```

打开 `http://127.0.0.1:8787`。这个模式的导游和游客可以使用独立浏览器，提交会写入被 Git 忽略的 `pilot/nimbus-pilot-data.json`。如需手机扫码，在可信测试局域网中，启动时同时设置 `PILOT_HOST=0.0.0.0`，并从电脑浏览器打开以电脑局域网 IP 构成的地址，例如 `http://192.168.1.40:8787`，再生成二维码。这个地址需要能被手机访问。

PowerShell 示例

```powershell
$env:PILOT_OPS_PIN = "replace-with-a-private-test-code"
$env:PILOT_HOST = "0.0.0.0"
node pilot/serve.mjs
```

## 部署内部线上测试

1）新建专门的 Google 测试表格和 Apps Script 项目。把发布包 `Apps-Script` 里的 `Code.gs`、`Core.gs` 和 `Index.html` 放到项目中。可从源码根目录运行 `node pilot/render.mjs`，在 `pilot/build/` 重新生成发布包。
2）在项目设置的脚本属性中配置 `PILOT_SHEET_ID` 为测试表格的 ID，`PILOT_OPS_PIN` 为至少 12 字符的内部运营访问码。
3）将脚本部署为 Web 应用，以部署者身份执行。为了让测试游客扫码后无需登录，访问对象选 Anyone（需要账户策略允许）。只将部署地址用于内部试跑。
4）打开部署生成的 `/exec` 地址。默认是导游入口，`?view=ops` 为运营后台。第一次写操作会自动建立 `PilotSegments`、`PilotReviews` 工作表。用实际测试手机验证连接和提交。
5）做一次三城联调，用同一个模拟团号建三个二维码，在独立浏览器分别提交。后台应看到同一团号下合计三条评价和三个服务段。

## 数据规则

- 团号在去除首尾空格和统一大小写后精确匹配。导游按照出团计划手填团号。
- 同团号、同城市、同导游默认复用第一张二维码。同城分队或返程可以明确新增服务段。
- 游客入口只包含服务段 ID。团号、城市、导游由服务器查询，评价以服务段 ID 为准。
- 总评必填。其他五项可留空或选「未体验」。低分沿用原系统的分数门槛，总评不高于 3 分或任一其他项目不高于 2 分。
- 测试版使用独立表格，不写入旧表单的 Feedback、Drive CSV 或 NAS。
